# Crew-wide Ground Review

Implement four fictional demo profiles (CM-1–CM-4), retaining legacy runs as CM-2. Each profile owns its readings, symptoms, check-ins, task baseline, active replay and history. Demo setup changes the active person's replay; a separate Load team demonstration seeds four new profiles and shares three explicit local demo snapshots, leaving one crew member awaiting a report.

Ground Review has a team overview, selected member analysis with interactive charts/evidence, previous snapshots, a crew summary export and ground acknowledgements/requests. It reads published packets, not unshared local runs. Late delivery does not replace a newer mission-time report. Snapshot time, received time, and missing/older data remain distinct; no cross-crew cognitive ranking or generated diagnosis.

Share a local demo packet without auth for same-browser two-window demonstration, clearly marked Local demo inbox. Cloud inbox uses existing same-account Supabase RLS. UI profile/role switches are demo controls, not production authorization. Optional wellbeing sharing is false by default and adds only latest self-report/task summaries. Ground responses are separate append-only envelopes referencing an immutable packet, using the existing JSON snapshot table with a discriminator; all readers filter response envelopes out of crew snapshots. No schema mutation or policy weakening is needed. Replies can queue offline and are shown to the corresponding crew/run; server storage and human acknowledgement stay distinct.

Tests: legacy fallback, member isolation, version selection, no-data vs no-concern, personal-baseline summary, consent exclusion, response linkage; Chrome end-to-end local team seed/share/review/request/crew return, cross-window refresh, offline/reload, cloud account isolation via mocked transport, existing journeys; production build and screenshot review. Use configured user author identity and publish feature branch after independent review.

Review fixes: demonstrations now use separate persisted batch IDs with archived-session selection; cloud crew reports are filtered before the ten-row archive limit so response traffic cannot hide reports. Sharing/export is disabled while consent changes persist. Ground freshness uses shared packet clocks, not unshared app state. Successful local two-tab and mocked cloud review/request/crew-response journeys include replay isolation, opt-in summaries, sign-out data hiding and repeated demo sessions. Tablet/phone screenshots inspected.

Final verification: 31 unit/render checks, production build/offline cache, and seven Chrome journeys (crew reporting, interactive charts, Signal Watch, daily checks, demo preferences, local team Ground Review, mocked cloud). Ground requests are surfaced on the corresponding crew home page. Returning from Ground Review reloads the saved active crew record to avoid resuming a stale tab copy. Follow-up independent review confirmed both reported findings resolved.
